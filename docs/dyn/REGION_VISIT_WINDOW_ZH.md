# 固定 1+2 Region 窗口与联合观测访问

这次修改从长测中已确认的候选计算与逐步选站问题切入。Global 仍是 shadow；Local 的运动、足迹、地形、制动和安装认证不变。没有添加 IoU 关联，也没有用新增 FREE 传播重新定义 Region。

## 当前实际行为

`RegionVisitWindow` 保留全部待探索 Region 的粗顺序。现有相对顺序不会因每帧收益变化重排；新 Region 以质心距离下界做插入，已提交的当前 Region 不被新发现的 Region 抢占。粗顺序仅用于调度，质心距离不表示已验证路线。

只有窗口内当前 1 个和前瞻 2 个 Region 会生成站位。默认每个 Region 每轮最多 4 个 Frontier 目标、每个目标 2 个站位，共最多 24 个站位候选。代表点按簇交错采样，并保留已选访问前缀；批次游标保留尚未处理的目标机会，不因首个大簇耗尽预算就永久漏掉其余需求。窗口外没有调用站位枚举、观测目标射线和终端路径准备。

当前 Region 内进行最多 3 个不同 Frontier 的访问前缀搜索，beam 宽度 8。每个 Frontier 的替代站位共同参与比较；同一 Frontier 在一条前缀中只出现一次。预计剩余观测集合求并集后计收益，已知格子不重复奖励。剩余收益估计与 ObservationTask 的冻结分母分离。

前缀同时考虑接入、路径转弯以及向后续两个 Region 的有限站位接续。已有的下一目标仍有有效候选时，保留访问顺序，重新验证站位和路线；缺失或失效的选项才退出。前瞻只影响偏好，不得否决独立有效的当前接入。

Region 访问的 scope 在任务成功发布或准确安装 ACK 后提交；同一 Region 换站保留 scope。新模式不再用 `BranchCommitment` 的原始 Frontier 格子交集反复决定这个访问是否延续。当前 Region 没有可用站位时，可以有界地准备后续工作；未完成需求仍留在粗顺序中，没有自动完成或永久拉黑。

## 粗连接与预算

立即执行的候选必须有 raw FREE 路线见证，斜步不能穿墙角，不在 Explorer 重复机体认证。先复用已检查路线，直连不成立时复用有界 A*。一次窗口选择共享最多 4096 次 A* 展开；未完成返回 SEARCH_INCOMPLETE，保留搜索，发布 REGION_VISIT_SEARCH_PENDING，不转成 DEPARTURE_UNSAFE 或目标不可达。

不可达端点不会再强迫 Python Dijkstra 展开整个起点分量。一个可复用的单字节布尔连通索引，仅作为 raw FREE 连接的必要条件；有向屏蔽边仍由实际搜索检查。四邻连通分量与禁止斜穿墙角的八邻模型一致。460×400 m / 0.2 m 地图上缓存约 4.6 MB，重建时另有临时掩码；不同几何或内容 revision 使缓存失效。路线和搜索采用有上限的缓存。缓存容量耗尽属于调度让出，剩余需求保留，不转成几何失败。机器人起点移动到相邻格时，可以续算近邻锚点的既有搜索；连接成功后重新验证当前起点接入与剩余路径。规划快照不会由路线缓存跨回调长期持有。

前瞻路线仍未查完时可以使用明确标注的距离下界作预测，`preview_estimated=true`。这种预测没有当前路径见证，不能作为立即下发给 Local 的路线；某个前瞻 Region 被提升为当前候选时，必须补做实际粗连接查询。

## 开关和观测

默认启用 `region_visit_window_enabled=true`。只在 hierarchical、Global 不参与 sparse routing 且几何自治开启时生效；route_cost 模式保留既有稀疏路线行为。

使用仓库或工作区启动脚本，原启动参数可以继续使用。添加 `--no-region-visit-window` 即可在新一轮启动中回到旧候选选择。原生 launch 使用 `region_visit_window_enabled:=false`。不是运行时动态切换参数。

`/explorer/region_sequence` 增加 `visit_window` 和 `visit_stats`；`/explorer/metrics` 增加 `region_visit_window_enabled`、`region_visit_window`、`region_visit_stats`。日志 `[REGION_VISIT_WINDOW]` 给出窗口、细候选与前瞻数量、访问前缀、A* 展开量、缓存命中、连通索引耗时/字节和预测状态。pending 站位在既有候选显示中采用独立颜色；前瞻候选不会冒充已验证的当前绿色候选。全部实际 Region 的边界仍发布。

## 验证与实际限制

315 项针对性 Python 回归通过，另已验证安装模块导入以及新旧开关的启动 dry-run。确定性回归覆盖：60 Region 只细化 3 个、同 Frontier 多站位联合选择、收益集合去重、前缀保持、预算续算、几何改变使旧路线失效、未验证前瞻不能成为当前路线、发布失败不推进窗口、安装 ACK 才提交，以及既有交接/取消行为。

旧阶段是现有 `build_frontier_candidates()` 的真实实现；新阶段额外包含联合选择和连通索引。输入来自同一份占据与已发布 Region 快照，未修改地形或通行能力。这里没有包含地图快照复制、Region 分组、ROS 回调调度和 Local 执行；不是整机延迟或 Z 字形减少比例。前瞻中有尚未认证的预测，日志明确保留该事实。

临时副本中曾尝试扩大测试范围，但该副本没有复制 maps/config/launch 等集成资源，也未启用 launch_testing fixtures，整套尝试未通过，不能作为全套回归结果；验证结论仅限上述针对性测试。没有运行本轮修改后的 Gazebo 闭环长测。

Region 的空间划分和 PersistentRegionTracker 尚沿用原实现。这一步不能证明旧 Region 0→12、62→90 的身份变化已被修复，也没有补齐逐格 measured-FREE 的来源记录。下一轮闭环长测应分别比较同 Region 内的路线反向、跨 Region 访问顺序、计算等待和真实执行等待；不能仅以减少 scope 释放日志宣布所有问题消失。

# 固定 1+2 Region 窗口与联合观测访问

这次修改从长测中已确认的候选计算与逐步选站问题切入。Global 仍是 shadow；Local 的运动、足迹、地形、制动和安装认证不变。没有添加 IoU 关联，也没有用新增 FREE 传播重新定义 Region。

## 当前实际行为

`RegionVisitWindow` 保留全部待探索 Region 的粗顺序。现有相对顺序不会因每帧收益变化重排；新 Region 以质心距离下界做插入，已提交的当前 Region 不被新发现的 Region 抢占。粗顺序仅用于调度，质心距离不表示已验证路线。

只有窗口内当前 1 个和前瞻 2 个 Region 会生成站位。默认每个 Region 每轮最多 4 个观测需求、每个需求 2 个站位，共最多 24 个站位候选。初次代表点按簇交错采样，随后优先保留同一小批需求；每项保留安全排序的首选站位和一个有空间差异的备选。窗口外没有调用站位枚举、观测目标射线和终端路径准备。

当前 Region 内进行最多 3 个不同观测需求的访问前缀搜索，beam 宽度 8。同一需求的替代站位共同参与比较，不因观察它的 Frontier 代表格改变就算成第二次访问。存在另一项具有边际信息收益的需求时，评分至少计入一次后续访问；只比较单站收益/距离的结果不会抢先击败联合方案。预计可见的剩余观测集合求并集后计收益，已知格子和重复覆盖不额外奖励。

`VisitDemand` 只是窗口内的有界选择缓存。首次比较时，将同一代表点的备选站位各自预测可见目标取并集，冻结为同一个目标域；每个站位只按自己预测可见的剩余部分计收益。准备候选在激活前保留此目标域，重新验证可见性和粗路线，不重新生成分母。同一已活动需求补站时，保留已有任务的目标与测量基线；完成判定仍只在现有 ObservationTask 上进行，预测不计为实测。

代表格离开当前 Frontier 时，只在当前 Region 的少量边界代表中寻找能够观察原固定目标的视角；检查至多 8 个目标代表与 8 个边界代表，不用区域形状的 IoU 建立身份。找不到可用关系时不强行关联；选择缓存可以回收，地图中的未知与未完成任务不会被标为完成。缓存仅保留当前窗口，至多 3×4 项，不维护另一张稠密地图，也不承担 Global 的空间身份职责。

前缀同时考虑接入、路径转弯以及向后续两个 Region 的有限站位接续。需求身份与目标域保持，访问顺序是可以调整的偏好。旧顺序在相同预算的 beam 中保留一个比较位置；如果其收益/时间比仍在当前最优的 15% 容差内则保留，否则采用更优顺序。调整顺序不结束未完成需求、不修改任务测量基线，也不抢占已安装的运动。

前瞻失败不得清掉当前 Region 已求出的联合访问。对每个前缀保留 A、A+B、A+B+C 的有限估价；统一用所有前缀都具有依据的最远共同层级比较。例如 C 无法接续但 B 可用，则比较 A+B；B 暂不可用则比较 A 内的联合访问，不退化成单站收益兜底。某个前缀少了未来腿不能因此获得“零接续代价”的不公平优势；未来无连接也不表示当前运动任务失败。`preview_unavailable=true` 明确表示有后续层级未参与估价，不能据此宣称整个未来顺序已获得几何认证。

访问代价统一成估计秒数：路径长度/名义速度 + 转角/名义角速度 + 大转角的停车起步开销；评分为预测新增观测并集大小 / (1 s + 总估计时间)。只在偏好层估价，不决定动作必须停车或可安全转弯。路径转角从原见证折线按 1 m 弧长采样、合并很短的尾段后计算，避免把斜线逐格的 45° 阶梯算成身体反复转向。原始路径不被这一步简化或替换，仍按原有 raw FREE 规则验证和交给 Local。

Region 访问的 scope 在任务成功发布或准确安装 ACK 后提交；同一 Region 换站保留 scope。新模式不再用 `BranchCommitment` 的原始 Frontier 格子交集反复决定这个访问是否延续。当前 Region 没有可用站位时，可以有界地准备后续工作；未完成需求仍留在粗顺序中，没有自动完成或永久拉黑。

## 联合前缀与真实任务推进

联合前缀分为候选草案和已安装计划。每次选择生成一份 `VisitPlan` 快照，记录当前 Region 内真正参与估价的需求顺序和站位；没有参与估价的旧需求不拼接到前缀尾部。准备候选、路线重验和任务发布都携带这份快照。选点函数不再直接覆盖已安装前缀，发布失败、搜索暂缺预算、待安装取消都不会推进它。后续两个 Region 仍只是接续估价，不被解释成已发布运动任务。

普通首次请求与 successor 交接都只有在收到准确匹配 task/version/request、具有 trajectory/candidate 身份的 `EXECUTION_READY` 后才提交对应快照。等待 ACK 期间即使又算出另一份草案，提交的仍是已发布任务携带的版本。已安装前缀中的后续需求及仍可用站位参与下一轮的滞回比较；站位失去可见性或粗连接依据时重新选，明显更优的访问仍允许按原 15% 阈值换序。

实测满足一个需求后，立即释放它在候选缓存和访问前缀中的引用，然后才能尝试准备好的 successor。候选与任务共享同一项缓存引用，因此切到另一项任务后，旧的 prepared/cached 站位也不能把这份已完成需求重新激活。缓存引用只随有界窗口、活动任务和待交接候选存活，没有新增永久完成 ID 表。地图里的剩余 UNKNOWN 保留，后续可以形成新的残余需求。到站但观测未满足只释放运动，不执行此完成回收，补站仍使用原目标域与测量基线。补站已经安装、ACK 途中原观测恰好满足时，仍接受真实运动安装，同时继承满足状态，不重开信息账本。

`[REGION_VISIT_PLAN]` 在实际发布、安装、信息满足、取消时记录 `plan/task/version/request/trajectory/region/demand/priced/remaining`；`REGION_VISIT_WINDOW` 的 `plan_state=DRAFT` 及 `plan_id` 表示当前预测，`installed_plan_id`、`installed_demand_prefix` 才表示实际提交及剩余访问。站位序列另记为 `station_prefix`。现有 metrics 中的 `region_visit_stats` 同步带这些字段，无 ROS 消息格式变动。

这一轮 335 项针对性 Python 回归通过，其中新增 18 项，覆盖实际发布与准确 ACK、期间重算、拒绝/取消/迟到 ACK、已满足需求跨任务回流、补站完成竞态、准备候选携带快照和已安装站位的滞回。同机三个已录 Campus 静态快照各测 3 次：修改前首次选择中位数 163.4/198.8/250.7 ms，修改后 165.0/208.7/235.9 ms；复用输入分别为 124.0/165.9/195.8 ms 和 121.9/173.4/195.3 ms。候选数均为 19/22/22，展开数均为 2688/3830/4096。它验证了这次串联没有增加候选或搜索预算；不是闭环 Z 字路线和停车比例的验收。

## 粗连接与预算

立即执行的候选必须有 raw FREE 路线见证，斜步不能穿墙角，不在 Explorer 重复机体认证。先复用已检查路线，直连不成立时复用有界 A*。一次窗口选择共享最多 4096 次 A* 展开；未完成返回 SEARCH_INCOMPLETE，保留搜索，发布 REGION_VISIT_SEARCH_PENDING，不转成 DEPARTURE_UNSAFE 或目标不可达。

不可达端点不会再强迫 Python Dijkstra 展开整个起点分量。一个可复用的单字节布尔连通索引，仅作为 raw FREE 连接的必要条件；有向屏蔽边仍由实际搜索检查。四邻连通分量与禁止斜穿墙角的八邻模型一致。460×400 m / 0.2 m 地图上缓存约 4.6 MB，重建时另有临时掩码；不同几何或内容 revision 使缓存失效。路线和搜索采用有上限的缓存。缓存容量耗尽属于调度让出，剩余需求保留，不转成几何失败。机器人起点移动到相邻格时，可以续算近邻锚点的既有搜索；连接成功后重新验证当前起点接入与剩余路径。规划快照不会由路线缓存跨回调长期持有。

前瞻路线仍未查完时可以使用明确标注的距离下界作预测，`preview_estimated=true`。这种预测没有当前路径见证，不能作为立即下发给 Local 的路线；某个前瞻 Region 被提升为当前候选时，必须补做实际粗连接查询。

## 开关和观测

默认启用 `region_visit_window_enabled=true`。只在 hierarchical、Global 不参与 sparse routing 且几何自治开启时生效；route_cost 模式保留既有稀疏路线行为。

使用仓库或工作区启动脚本，原启动参数可以继续使用。添加 `--no-region-visit-window` 即可在新一轮启动中回到旧候选选择。原生 launch 使用 `region_visit_window_enabled:=false`。不是运行时动态切换参数。

`/explorer/region_sequence` 增加 `visit_window` 和 `visit_stats`；`/explorer/metrics` 增加 `region_visit_window_enabled`、`region_visit_window`、`region_visit_stats`。日志 `[REGION_VISIT_WINDOW]` 给出窗口、细候选与前瞻数量、访问前缀、A* 展开量、缓存命中、连通索引耗时/字节和预测状态。`demand_prefix`、`selected_demand`、`selected_visible_cells`、`selected_target_cells` 分别表示需求访问顺序、所选需求、当前站位预测可见的剩余目标数和冻结目标域大小。它们不改变 ROS 任务消息格式。pending 站位在既有候选显示中采用独立颜色；前瞻候选不会冒充已验证的当前绿色候选。全部实际 Region 的边界仍发布。

访问估价参数为 `region_visit_nominal_speed=0.5` m/s、`region_visit_nominal_yaw_rate=0.8` rad/s、`region_visit_stop_turn_angle=0.8` rad、`region_visit_stop_restart_time=1.0` s、`region_visit_reorder_ratio=1.15`。前四项是选点估计，不是 RL/Controller 速度限值、实际交接阈值或停车授权；最后一项只抑制微小收益变化导致的换序。它们由 Explorer 声明并随参数快照记录。现有日志与 `visit_stats` 增加 `predicted_gain`、`estimated_time_s`、`travel_time_s`、`turn_time_s`、`stop_turn_time_s`、`continuation_time_s`、`preview_regions_priced`、`preview_unavailable`、`reordered`，便于区分正常联合比较、未来缺失和有收益的重排，不新增高频逐候选日志。

## 验证与实际限制

2026-10-31 第二次短测后的顺序修正新增了当前联合访问不被未来断连清空、统一未来估价层级、少量残余可重排但不被完成、顺序滞回、转向时间偏好和栅格阶梯估价的确定性回归。该修正不涉及下面记录的 KnownFreeSearch 失效与淘汰问题，闭环 Z 字路线比例仍需后续实测。

2026-10-31 的站位修正通过 318 项针对性 Python 回归，覆盖：同需求多站位共享固定目标但预测可见集合不同、先定站位会错过更好后续接入、不同 Frontier 视角不重复访问同一需求、边界移动仍保留需求顺序、墙体不允许错误关联、准备/激活/准确安装 ACK 保持身份，以及补站保留测量基线。

在这次 Campus 录下的三个静态占据/边界快照上，候选与联合选择首次调用中位耗时从修正前约 163/201/230 ms 变为 186/198/217 ms；同一输入复用后的中位数从 113/153/195 ms 变为 103/155/155 ms。每个数来自同机 3 次实验。没有恢复全部光学证据、失败和任务历史，不包含 Region 分组、ROS 调度或 Local 执行；不能据此宣布 Z 字路线或停车比例已改善。

短测末尾搜索因依赖变化重启、容量淘汰而不能持续推进的问题，仍需独立处理。本轮站位修正没有修改 KnownFreeSearch 或 BoundedVisitRoutes 的失效/容量策略，不代表该 45 秒等待已经修复。

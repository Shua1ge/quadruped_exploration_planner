--------------------------------------------------------------------------------
0. 先认人:这套系统里的对象
--------------------------------------------------------------------------------
每个对象讲三件事: 它是什么 / 谁拥有它的终局 / 它住在哪。
"终局"= 一个对象一生只能有一次的结果;有了终局,这个对象就关账。

  任务(Task)
    是什么   一次"去某处看某些格子"的意图。
    终局归属 Explorer(宣布 SATISFIED——真的看到了才算)。
    住哪     Explorer 的任务表里。【独立对象】: 它可以引用区域或
             分支的 ID,但图上删节点、拆分支、合并谱系,都【不会】
             改变任务的终局。任务终局只能由 Explorer 写。

  承诺(Commitment)
    是什么   Explorer 对一个区域工作集说"我现在在这片干活"。
    终局归属 Explorer(经承诺转换入口释放: 完成/返航/取消/健康/
             通道阻断,五类都合法,走同一入口)。
    住哪     Explorer,挂着区域/分支引用。

  候选(Candidate)
    是什么   Local 为当前任务生成的一个起步方案(路线+合同)。
    终局归属 Controller(装载裁决: 接受装载 / 拒绝装载)。
    住哪     Local/Controller 之间,即用即弃,不进长程记忆。

  轨迹(Trajectory)
    是什么   Controller 手里一条被装载的样条,正在跟或排队跟。
    终局归属 Controller(执行结果: 执行完成 / 执行中止)。
    住哪     Controller。

  运动尝试(Try)
    是什么   Local 为推进任务发起的一轮运动努力。一轮尝试里可能
             生成多个候选、装载多条轨迹。候选被拒一次【不等于】
             尝试穷尽。
    终局归属 Local(宣布 EXHAUSTED——候选族试完或尝试预算用完)。
    住哪     Local 的执行记录。

一句话记住分工:
  Explorer 管"看没看到"(任务),
  Local   管"试没试完"(尝试),
  Controller 管"这条轨迹走没走完"(轨迹),
  Global  管"这地方叫什么"(身份)。
  任何人都不替别人下结论,也不替别人改结论。

1. 状态从哪来:每个事实的唯一来源
--------------------------------------------------------------------------------
规则(规格 v3.3-a): 每个字段、每个结果,必须有【唯一来源】。
"不新增话题"不是正确性标准,唯一来源才是。执行协调组件是对外状态
的【唯一汇总出口】;它只归并转发,不重新裁决——它无权把"尝试穷尽"
改写成"任务失败",也无权把"轨迹走完"改写成"任务完成"。

  事实                              唯一来源        说明
  ─────────────────────────────────────────────────────────────────
  候选装载结果 ACCEPTED/REJECTED    Controller      装载 ≠ 走完
  已装载轨迹的执行结果              Controller      完成或中止
  当前运动状态(行进/STOPPING/      Controller(实测) 这是"现在",
  STOPPED)                                          不是"结果"
  起步候选安全判定                  Local           统一验证+安全仲裁
  运动尝试终局 EXHAUSTED            Local           穷尽时才有
  观测任务终局 SATISFIED            Explorer        真实观测证据
  区域/分支身份                     Global Registry extend/split/…

两条正交的状态维度(不许塞进同一个互斥枚举):
  维度一【现在怎么样】: 行进中 / 制动中(STOPPING)/ 停稳(STOPPED)
  维度二【结果是什么】: 轨迹终局 / 尝试终局 / 任务终局
两个维度同时读,才是完整现场。例如"机器人已停稳 + 上一条轨迹执行
结束 + 观测任务还没满足"是一个完全合法的组合。新接口必须能直接
表达它,不允许让 Explorer 从字符串和时间戳去猜。

2. 终局缓冲:保留、有界、满载怎么办(三条过程共用)
--------------------------------------------------------------------------------
这是三条过程都要经过的机制,先单独讲清,后面直接引用。

正常时:
  任何终局(轨迹的/尝试的/任务的)产生后,进入一个小缓冲区,
  保留到 (a) 消费者(通常是 Explorer)确认消费,或 (b) 被同一个
  对象的替代结果/显式失效关系取代。
  注意"同一对象内": 轨迹终局只能被【这条轨迹】的新结果取代,
  任务终局只能被【这个任务】的新结果取代。不存在"Explorer 的
  状态覆盖 Local 的状态"这种跨角色覆盖阶梯。

满载时(消费者暂时离线,执行侧还在产生结果):
  缓冲有上限。满了以后按下面的规则办,不静默丢,也不堵安全:
    1) 当前活动对象的身份与它的终局【永远保留】——这是重启后
       对齐的锚。
    2) 旧记录按明确规则压缩([待填]: 建议按对象保留"最后终局",
       丢掉更早的中间态;每次丢弃写日志)。
    3) 消费者落后超过保留范围时,执行侧发布一个【缺口事件】:
       "从 revision X 到 Y 的记录已不可得"。说出来,不装没事。
    4) 消费者恢复时: 先读当前对象快照重新对齐,再从缺口事件知道
       中间一段不可考;需要补偿的由上层按快照重算。
    5) 任何时候,记录消费【不得阻塞安全停车】。安全反射不经过
       缓冲,直接执行。

Explorer 重启时:
  执行状态只能帮它恢复【运动上下文】(机器人在动吗/停稳了吗);
  观测目标集和承诺上下文,从 Explorer 自己的任务快照恢复——
  不从最近终局反推(终局里没有目标集是什么的信息)。

消费语义(对应验收 B6):
  同一对象的同一终局可以重复传输;但对决策产生的【副作用】恰好
  一次。靠"消费确认 + 对象 ID + 终局 ID"去重,不靠"收到过就
  永久忽略"——后者处理不了消费过程失败和重启恢复。

3. 过程A:正常滚动交接(任务完成后不停顿地换任务)
--------------------------------------------------------------------------------
目标: 任务 T1 观测完成,系统换上任务 T2;期间机器人不停下、
      不倒退、不重复起步。

先摆清三个对象的关系(规格 v3.3-c):
  活动任务 T1   正在被 Local 执行的任务。
  后继任务 T2   已经选定、正在准备的任务。
  候选 C2       为 T2 生成的起步方案。
  "一单在飞"只约束【请求-响应对】: Explorer 对 Local,同一任务
  同时只有一个未决请求。它【不】禁止"T1 还没收尾就开始准备 T2";
  它也【不】允许"T2 准备好了就自动开始执行"。准备和授权是两道
  独立的门。

步骤:

  A1 观测证据到位
     什么发生: T1 的目标格被真实观测解析。判定依据是每格的
     观测来源标记(sensor_observed)对照任务创建时记下的
     initial_sensor_revision——不是"地图被谁置成 FREE",
     不是"机器人到过某个点"。
     谁裁决:   Explorer 宣布 T1 = SATISFIED。其他角色无权替它
     宣布——Local 不能因为"轨迹走到了"就宣布任务完成。
     岔路:     无(证据不够就不宣布,继续执行)。

  A2 承诺转换(入口,类型1: 观测完成)
     什么发生: T1 所在的承诺经同一转换入口释放/交接;读取兄弟
     区域的残值摘要;选定下一片区域工作集。
     过哪道门: 五类转换之一,走同一入口——这是"漏释放不可能"
     声明成立的前提(测试覆盖前只说"入口统一了")。

  A3 后继任务准备(允许与 A1/A2 并行)
     什么发生: T2 创建(新 task_id、task_version=1),目标格
     过滤,站位建议生成。
     边界:     此时不发任何运动指令;T1 的执行完全不受影响。
     教训:     "一个请求在等响应"不禁止"另一个任务在准备"——
               把这两件事捆在一起,是过去交接变慢的常见原因。

  A4 后继发布(P1)
     什么发生: T2 下发给 Local。
     过哪道门: 从此刻起,"一单在飞"对 T2 生效(T2 只有一个
     未决请求);但 T2 的下发【不】自动授权任何运动。

  A5 候选生成与装载
     什么发生: Local 为 T2 生成候选 C2;Controller 裁决装载
     结果: ACCEPTED 或 REJECTED。
     关键:     这是【装载】裁决,不是运动成功的证明。REJECTED
     只说明"这条候选装不上",不说明 T2 失败,更不说明区域
     不可行。装载成功也不许庆祝——执行结果还没来。
     岔路:     REJECTED → 回到候选生成,且下一次生成必须记录
               "相较上次改变了什么"(换了什么假设)。新请求 ID
               【不算】改变。(重复拒绝的处理见过程B。)

  A6 合法切换点
     过哪道门(全部满足才切换):
       a) C2 已被 Controller 接受装载;
       b) 旧执行的安全前缀到达一个安全让位点;
       c) 执行授权从旧轨迹转移到新候选。
     期间的纪律: 旧前缀继续执行【仅当它仍然安全】。新观测发现
     障碍,允许随时打断它——安全优先于交接平滑。
     记账:     切换点前后的每一次停顿,都必须带【原因字段】+
     时间记录。无必要的协议停顿是回归;真实安全原因的停车不是。

  A7 旧对象退役
     什么发生: T1 的终局进入终局缓冲(§2),Explorer 消费确认后
     T1 关账;旧轨迹对象显式退役,保留谱系引用。
     边界:     退役是【显式动作】,不是"被新任务挤掉"。

  A8 验收读数(对应规格 B1/B2)
     B1a: A1(SATISFIED)→ A4(发布)的延迟,单独测。
     B1b: A4(发布)→ A6(实际切换)的延迟,单独测。
          合并成一个"总延迟"会掩盖"决策很快、执行一直等"。
     B2:  旧前缀从 A1 到 A6 持续执行、未被无故打断。
     失败信号: 无必要的协议停顿 / 回退 / 重复起步(安全原因的
          停车除外,按原因字段区分)。

--------------------------------------------------------------------------------
4. 过程B:起步失败 → 区域保留(一次拒绝不杀死一个信息需求)
--------------------------------------------------------------------------------
目标: 起步候选被拒绝时,系统在有界尝试内把"失败"放到正确的
      作用域上——站位/合同,而不是整条分支;信息需求保留,
      换方案再来。

先记住一条分层(规格 v3.3-d):
  一个起步候选被拒绝 ≠ 这一轮运动尝试已经穷尽。
  穷尽 = 候选族试完,或尝试预算用完。在这之前,状态是"还在试"。
  (v3.2 的演练B 少了中间这层,会把"单次拒绝"直接升级成
  "整次穷尽"——那是老卡死的配方。)

步骤:

  B1 候选起步被拒
     两种来源: Controller 装载拒绝(REJECTED),或 Local 统一
     验证拒绝。无论哪种,先分类(§1.6 五类):
       实际占据反证 / 地图过期 / 姿态变化 / 预算耗尽 / 合同不适用。
     分类决定下一步走哪条岔路,不是所有拒绝都同罪。

  B2 记录失败事实(此时不生成持久证据)
     记什么: 失败类型 + 位置(哪段出发连接/哪个站位)+ 适用
     运动条件。
     纪律:   持久证据要等穷尽才入图(见 B5)。单次拒绝就往图上
     写"这里不行",是越权。

  B3 同一任务内有界重试
     什么发生: 改变起步方式或路径假设,再试。
     纪律一:   每次重试必须记录【相较上次改变了什么】——换了
               站位?换了接近方向?换了路径假设?新请求 ID
               【不算】改变(只换编号不换假设 = 白烧预算)。
     纪律二:   预算有界([待填]: 尝试次数或时间上界)。
     岔路:     分类为"地图过期"的等待分支——就地等待/重查,
               不算起步失败;但必须报告等待原因与退出条件
               (重试上限/revision 前进/上层超时),不允许
               不声不响地无限等(验收 B4)。

  B4 穷尽裁决
     过哪道门: 候选族穷尽,或尝试预算结束。
     谁裁决:   Local 宣布本轮运动尝试 = EXHAUSTED。
     注意:     这是【尝试】的终局,不是任务的终局,更不是
               区域的终局。

  B5 失败证据入图(作用域收窄)
     什么发生: failure_evidence 挂到图上,必须带三要素:
       来源          —— 哪次尝试产生的
       适用运动条件  —— 哪个站位/哪段出发连接/哪个合同
       撤销条件      —— 什么观测出现时失效
     作用域由证据类型决定: 一次起步失败约束【该站位/该合同的
     再次起步】;只有路线级证据(承诺转换5)才约束分支。
     Global 负责存储,但【无权】把它放大成"分支不可通行"。

  B6 Explorer 调整
     什么发生: 信息需求保留(该看的格子还该看);Explorer 调整
     接近方案或站位。
     教训规则: 换站位不一定有用——如果几个站位共用同一段失败的
     出发连接,换更远的目标照样失败(这正是过去卡死的形态)。
     选新站位时必须检查: 新站位到目标的出发连接是否与失败记录
     重叠。重叠 = 大概率重演,跳过或换接近方向。

  B7 证据的撤销
     过哪道门: 【满足该证据自己写明的撤销条件】时撤销。
     不是"地图有新帧就撤"——新帧可能根本没看原障碍;
     不是"别处地图更新就撤"——别处更新与当前出发方向无关。

  验收挂钩(规格 B3/B4):
    通过: 后续决策仍把该区域列为候选(只是换了路径/站位/方式);
          证据在满足撤销条件时确实被撤销。
    失败信号: 一次起步失败后该 Frontier 永久消失(作用域被
          违反);或换站位后重复走同一段失败出发连接(教训
          规则没被执行);或等待分支无声无息(没有原因和出口)。

--------------------------------------------------------------------------------
5. 过程C:取消 → 迟到消息(旧执行不许复活)
--------------------------------------------------------------------------------
目标: 用户取消后,无论迟到的消息长什么样,旧执行不复活;
      机器人干净地停稳。

步骤:

  C1 取消指令进入
     什么发生: 用户取消 → 承诺转换入口(类型3: 用户取消)。
     承诺释放;区域记忆保留(看过的还是看过的,不因为取消
     而遗忘)。

  C2 三道闸依次落下
     a) 版本失效:  当前 task_version / trajectory_id 标记作废;
        之后带旧版本号的消息一律拒绝。
     b) 任务栅栏:  RETIRE_TASK 下发,旧任务不再接受任何推进。
     c) 执行授权撤销: 授权是独立维度——没有授权,任何候选
        即使装上了也不许开始执行。
     三道闸缺一不可: 只做版本失效不管授权,就会出现"取消后
     旧候选被重新接受"这种复活路径。

  C3 命令归零 → 停稳确认
     命令归零和机器人停稳是【两个阶段】: 归零之后仍有制动
     位移,这是动力学,不是故障,更不是"向前冲"。
     停稳由实测速度/角速度(及必要的姿态条件)确认;
     不由 ETA 确认,不由"命令已发出"确认。

  C4 迟到消息到达(测试注入)
     场景: 取消之后,旧轨迹的 ACK / 终局才慢悠悠到达。
     处理: 版本栅栏直接拒绝;拒绝这个动作本身【不产生任何
     副作用】——不重发、不重授权、不改变承诺状态。
     (配合 §2 消费语义: 重复传输无害化。)

  C5 验收观察(规格 B5,v3.3-c 收窄)
     同时观察三样东西,不凭单一信号下结论:
       执行授权 —— 取消后是否出现【重新接受旧候选】或
                    【再次授权旧执行】?出现 = 栅栏漏,失败。
       命令输出 —— 是否有非零运动命令持续流出?归零瞬间的
                    有界制动输出正常;持续非零 = 失败。
       实际停车 —— 停稳是否在实测意义下达成;制动位移属于
                    动力学,【不】算失败信号。
     判定红线: v3.2 写的"取消后任何短暂向前冲都是栅栏漏"
     【作废】。失败判据是"取消后旧执行被重新授权";制动

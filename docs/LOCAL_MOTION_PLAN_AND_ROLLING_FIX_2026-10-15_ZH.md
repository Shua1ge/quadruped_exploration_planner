# Local 出发、终端退出与滚动衔接修复

2026-10-15。本轮对应运动安全审查中的第 3、4、13 项，以及它们依赖的进度跟随耦合。修改集中在 Local、Controller、Bspline 消息和相关注释，不改变 Explorer 的信息完成账本、Global 图结构、真实足迹/硬余量、精确安装误差及侧移物理预算。

## 实际行为变化

Local 使用 TaskDeparturePlan 比较直接出发与固定朝向直行到可转位置的转换；目标与这次转换分开记录。已选转换的曲线拟合或安装失败，不会自动清除转换并消耗另一个准备点；真实捕获或失败仍由既有转换状态机处理。

taskTerminalExitPlan 替代固定 yaw→yaw+π 的站位重启规则。优先检查向接近路线连接的方向；直接转向不适用时，比较 0.4/0.8/1.2 m 直行后转向及完整停止前缀；再比较其他有限方向的普通退出。同一退出方向或同一转换必须在前后 ±0.15 m 捕获位置全部通过，不能把不同位置各自可用的不同出口混成一份证明。选点、最终样条认证、实测到站复查共用该规则。

这份退出证明仍是近端有限能力。它不保证任意下一 Goal，也不会直接自动执行旧证明里的退出动作。下一任务按新目标、实际位姿和最新地图重新选择/认证。左右蟹行保留原有有界恢复通道，没有因站位准入而增加无限侧移授权。

有效观测终点通过曲线版本和同任务请求刷新保持。有限连接搜索失败会报告 TASK_OBJECTIVE_RETAINED 并消耗既有尝试预算，不改成远端站位不通。曲线拟合/终验失败和 Controller 安装拒绝不再直接将站位加入拒绝表；新的硬几何、终端退出或可见性证据仍能撤销终点。已有站位效果失败、实际执行失败和恢复终局规则继续生效。

preferred 净空拟合失败后，在同一目标/接近路线尝试 hard 余量；删除借这次失败反复排除终点、另选“更宽终点”的优化循环。正常重试可以在既有失败次数内比较同一终点的其他 approach，不通过同一次 FSM 回调重复拟合同一种子来伪装成不同尝试。

普通通行端点与驻留站位使用不同保持条件。驻留目标保持到捕获或明确失效；通行端点在距离降到 max(0.40 m, 实测速度×后继准备时间+0.20 m) 内时向前延伸。这样后继能够在旧段的终端捕获之前准备，不能把反复重建旧短段算成有效滚动。

Bspline 新增 use_measured_progress。它显式决定参考时间还是实测空间进度，独立于执行模式、速度上限及 min_forward_command。Local 任务轨迹在 normal 模式也启用实测进度；Controller 使用实际身体匹配位置、单调进度及前视目标，不让参考时钟在身体未动时先跑到终点。最低前向命令只负责已有前向步态合同；固定朝向侧移继续由自己的捕获逻辑控制。Local 的正常进度、实时安全、认证转向方向、ACK 提交及超时对账传播同一字段。

普通终端捕获的持续零命令、实测停稳和 FINISHED 保留。移动接续仍需位置、朝向、速度、准确任务/轨迹 ACK；不通过时不能强行安装。没有合法后继时仍安全收束。

## 验证结果

隔离目录 /tmp/scan_terrain_validation/SCAN-Planner；独立构建/安装目录 /tmp/local_motion_contract_20261015/build 与 install。测试进程只使用 150–199 范围内的独立 ROS 域和合成身体/传感数据，没有向现场仿真域发送运动命令。

44 项 LocalTaskPlanner C++ 测试与 97 项执行工具 C++ 测试通过。覆盖单向通道不强求原地掉头、所有捕获姿态必须有同一出口、转向位置合格但返回停止前缀不合格时继续寻找更远转换点，以及通行端点延伸与驻留目标保持的区别。

完整原有及新增 ROS 进程回归中 59 项通过，另两项新增目标/滚动测试通过，合计 61 项。新增场景覆盖：normal 模式在最低命令为零时仍使用实测进度；身体未动时参考不前冲；移动中的合法后继直接接续；窄观测站位保留认证前向出口；安装被拒后重试同一站位与候选身份；Local 在旧通行段捕获前延长终点。转向、停稳、蟹行、剩余旋转新障碍、ACK 超时、取消与退役等既有场景一并通过。

日志位于 /tmp/local_motion_contract_20261015/cpp_local.log、cpp_utils.log、runtime_full.log、runtime_objectives.log。CMake 的 Python 测试发现仍提示其解释器没有 pytest；上述 ROS 用例通过 /usr/bin/python3 直接运行 unittest，并非把未运行的 pytest 计入通过数。

## 部署与能力边界

Bspline 消息布局发生变化，需配套重编译 Planner、Controller 及所有消费者，旧进程不能热接新消息。实际工作区补丁应用后应完整构建主导航树，再结束旧导航进程、在新终端加载新 install 启动。构建本身不会替换已运行进程。

本轮验证证明了几何动作选择、目标保持、进度与接续协议；合成执行器不代表 legacy ONNX 在所有地形的真实响应。此前确认的侧移提前制动/下游命令变化率与身体停止能力问题，以及完整地形支撑通行模型，不在这次修改中宣告解决。现场需看实际驻留、转换、接续与停止结果，不能以曲线生成或 ACK 代替真实运动成功。

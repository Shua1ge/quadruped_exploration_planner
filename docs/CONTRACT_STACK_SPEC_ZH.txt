0.1 为什么重写
  系统从"SCAN-Planner 移植"演化到"任务契约 + 两级承诺 + 运动耦合",原始叙事
  (导航局部规划器 + 探索附加层)已经无法解释系统是什么。同时,长程探索跑不完
  的失败叠加了三类问题(操作/标定/设计),必须用权威边界把它们切开。本文件
  完成三件事:
    (a) 把系统的记忆结构收敛为"度量层 / 结构图 / 执行窗口"三样维护
        结构 + 一组独立对象(任务/尝试/轨迹/承诺)。图上可以挂引用
        与摘要,但任务终局是 Explorer 持有的独立对象,不随图节点
        删除/分支拆分/谱系合并而隐式改变(v3.3-e);
    (b) 把三个角色(Explorer/Global/Local)的职责按"对象生命周期的权威"重写;
    (c) 把所有已讨论的思想(TRG/RB-TRG/STG/TGH 吸收、事实流、区域工作集)
        放进统一框架,并给未定部分留出待填空间。

  总纲(v3.2,采纳评审终审意见): 本次重构的核心 = 单一任务权威 ·
  独立执行生命周期 · 明确的失败作用域 · 可退役的旧职责。三张图与
  新拓扑引擎放在这个核心【之下】——它们是核心的支撑结构,不是贡献
  本身;任何一处图结构的收益陈述,都要能还原为上述四条核心之一。

1. 第一性原理:五个不可归约的问题,权威按对象生命周期划分
--------------------------------------------------------------------------------

系统要回答的问题,去掉互相可推导的之后,剩五个。回答采用不同时间
尺度(v3.3-f): 决策拍(0.25s)/执行拍(0.1s)/结构拍(~1s)各自规定
允许的数据年龄与计算预算([待填])——异步更新是合理的,过大延迟
不是架构优势。

1.1 权威的定义(v3.1 修正)
  "每问一权威"约束的是**某个明确状态的写入权与终局裁决权**,不是要求
  其他层完全不能判断、不能维护状态:
    - Controller 判断"这条轨迹走完了" ≠ 它维护了第二本观测账本;
    - Local 判断"这批起步候选都不安全" ≠ 它越权判断"这个区域不可观测"。
  真正的禁令是:不同对象的结果,不得通过 FINISHED/BLOCKED/REACHED 这类
  宽泛名字混在一起,再被另一层解释成更大的失败或完成。

1.2 五问与对象权威表(v3.1 核心边界)

  对象          生命周期权威      终局裁决            裁决依据
  ─────────────────────────────────────────────────────────────
  观测任务      Explorer          SATISFIED /         真实观测证据
                                  换站位 / 切任务      (目标格解析)
  运动尝试      Local             EXHAUSTED           统一验证+安全仲裁
  执行轨迹      Controller        SUCCEEDED/REJECTED  ACK 事务
  区域可达性    Explorer(经证据)  同一转换入口         证据分类(§5)
  分支身份      Global Registry   extend/split/       图拓扑+迟滞确认
                                  merge/vanish

  事实载体与消费者:
    观测任务  → 任务对象(Explorer 持有,observation_lifecycle 落地)
                + 图上仅挂引用/摘要,非终局载体(v3.3-e)
    运动尝试  → 事实流(ExecutionState 扩展)+ failure_evidence
    执行轨迹  → TrajectoryAck / ExecutionState(版本化 ACK 事务)
    区域可达性 → failure_evidence(带来源/适用运动条件/撤销条件)
                → Global 约束存储(作用域纪律见 §5)
    分支身份  → delta/snapshot(BranchRegistry 输出)

1.3 三种"自由"分别命名(v3.1-b,不再统称"已知自由空间")
    观测证据自由(Explorer)  : "积累的观测说这里没有障碍"——可逆、有迟滞、
                              0.2m 二维+z 摘要。
    投影通行自由(Global)    : "在指定投影与通行模型下,这里连通"——骨架
                              语义,来自 Local GridMap 切片(非 Explorer
                              栅格快照,现行生产链保留)。
    执行合同自由(Local)     : "按当前姿态、速度和执行合同,这一步可执行"
                              ——瞬时、体素级、有噪声。
  三者分歧按 fail-closed 处理(见 1.5),但分歧本身必须先分类(见 1.6)。

1.4 三条纪律
  (a) 每图一问:每种维护中的表示回答一个不可归约的问题;能回答已有问题
      的是"视图",不是"结构"(实证:safe_region/骨架/渔网曾回答同一问题,
      收敛为一张网)。
  (b) 每问一权威(按对象生命周期):见 1.1/1.2。
  (c) 层间只走消息:三张图之间不存在直接读写;任何跨层数据需求走协议
      (第 4 节),并且先过权威归属检查。

1.5 故意不同步的冗余(v3.3-f 修正)
  同一巷道在三张图里有三个投影:执行窗口 0.05m 体素(瞬时)、度量层 0.2m
  证据格(0.25s 延迟、持久可逆)、渔网分支(~1s 延迟、结构稳定)。
  时间尺度的差异是特性:执行要新鲜、决策要保守、身份要稳定;但每个
  投影必须规定允许的数据年龄上限([待填])——异步合理,过大延迟不是
  优势,是待收敛的参数。分歧出现时按 fail-closed 处理(作用范围见
  1.6),不做"统一地图"。

1.6 分歧分类(v3.1-e,拒绝自动升级)
  Local 可拒绝执行,但拒绝必须分类:
    实际占据反证   → 传感器看到的占据与规划假设冲突 → 上报 blocked
    地图过期       → 分歧可由更新消除 → 就地等待/重查,不上报
    姿态变化       → 估计漂移 → 触发局部重查
    规划预算耗尽   → 上报 EXHAUSTED(运动尝试终局)
    运动合同不适用 → 上报合同级失败(如 STOPPING 期间拒绝新轨迹)
  一次局部拒绝【不】自动改变持久拓扑,【不】自动把区域判成不可观测。

  fail-closed 的作用范围(v3.3-f,拒绝"一处过期全身停车"):
    Local 当前执行合同不满足 → 停车/不起步(合同范围内,照旧)
    远处结构信息过期         → 限制依赖它的路线选择与跨分支动作;
                                【不】自动停掉已认证的安全前缀
    地图过期就地等待         → 不生成持久阻断证据,但必须报告等待
                                原因与退出条件(重试上限/revision
                                前进/上层超时)——不是"完全不上报"

2.1 度量层(Explorer 持有;Q1 的权威,权威表述见下)

  数据结构:
    data      int8      三态 UNKNOWN/FREE/OCCUPIED
    evidence  int16     有界证据 ±32(占据可逆的机制)
    [D-13]    sensor_observed u32  观测来源标记(现实现 u64,收窄待改)
    [F1]      地面摘要用途/来源/编码待定;不预设 z_mean f16 + z_cnt u8
              (推荐感知侧同源生成,见蓝图 §8.2/§8.5/Q16)
    [D1]      分块     32×32 格(6.4m)世界坐标编址,惰性分配
  分辨率/覆盖: 0.2m;固定尺寸 → D1 后逻辑无限,内存随探索面积。

  权威表述(v3.1-c): 本层回答"积累了哪些观测证据、还缺哪些信息"。
  它【不】回答"能不能踩"——地面支撑、坡度、悬空、机体净空是后续地形
  与运动模型的输出,不是三态栅格+z_mean 已具备的权威。

  存什么: 三态占据的"当前判断"(不是观测记录——无时间戳历史、无点云
          回放、无语义)+ 地形摘要。evidence 是判断的依据,data 是判断
          的结论。
          另有两样【必须有】的元数据(v3.2-b,评审指正): 每格观测来源
          标记(sensor_observed)与地图 revision——完成判定用的是
          sensor_observed_cells × 任务创建时 initial_sensor_revision
          (observation_lifecycle.py:60-70),不是"data 变 FREE"。"不保存
          原始历史"不等于"不需要观测来源与更新标记"。位宽收窄
          u64→u32(D-13): 版本号语义必需,位宽非必需,零语义损失;
          现实现仍 u64。
  刻意不存: 3D 结构(z 带投影丢弃)、语义、每次观测的原始数据、格子级
          时间序列、通行性结论。

  写者: cloud_callback 单回调组(0.25s 节流;perf 分支向量化 1.4ms)
        —— 单写者是这张图正确性的根基。
  读者(同图两读,合法): 决策拍规划(frontier/A*/候选)+ 完成度判定
        (目标格 unknown→解析)+ 兄弟残值摘要(按区域归组)。
        同图两读不产生对账;对账只发生在"两个结构答同一问"。

  凭什么独立: 删了它,系统失去"积累的判断"——执行窗口只记得眼前 10m,
          渔网只有骨架没有格子级证据;探索决策(哪里没看、目标格解析
          没有)无处落脚。

  接口: ① 感知写入(单写者);② 决策读(快照);③ 完成度判定读数。
  【注意】它不向结构层供料——结构层的原料来自 Local 的 GridMap 切片
  (v3.1-b 修正,见 §0.2)。

  演进落点: perf(向量化/掩膜/tobytes/revision 门控)、D1(chunk)、
          F1(z 摘要通道)。
  失败模式: 证据抖动(完成度判定需迟滞)、越界=墙(D1 前的长程上限)。
          (F4 tolist 序列化已在主线修复,frontier_explorer.py:4500 用
          tobytes()——v3.2-a 从本清单移除。)

2.2 结构层渔网(Global 权威持有 + Explorer 副本;Q2 的权威)

  数据结构:
    节点:  id(u64 世界量化锚定) · pos · stability · clearance ·
           state(确认计数) · branch_id([E1])
    边:    邻接对 · risk([F1]) · length · branch_id([E1])
    区域:  region_id · lineage · {branch 集合} · residual 摘要
    锚点:  起点原点位姿 + 量化参数(Registry 持有,重锚变换留接口)
  构建: 波前传播增长(从起点/已有节点向外),节点锚定;局部地形反证
        时允许局部删除,区域属性由周围节点继承。
  生命周期(v3.1-f 修正): ID 不复用;对象可失活、退役,保留谱系与
        必要的历史引用。环路闭合 ≠ lineage 自动统一——连接关系新增
        不代表两个历史对象变成同一个;merge 需要独立判据([草案])。

  两层身份分离(v3.4-a): 网格元素(节点/边/网格单元)与分支身份是
        两个层级。网格元素可因重建、细化而增删;只要空间连通与
        分支语义不变,稳定分支身份保持——数值细化(把粗边拆成短边)
        【不】自动构成 BranchRegistry 的 split,不引起区域换名、
        承诺迁移或任务版本变化。分支身份变化只由四事件(真实拓扑
        语义变化)定义。
  数值单元(是否采用面片待定)是构建引擎内部表示,【不】默认进入
        delta/snapshot 对外分发;对外发布稳定连接、门户与必要的
        几何支撑(边缘效率)。TRG 三角环不等于三角剖分,见蓝图 §8.3。
  局部细化 = 诊断后的表示修复(v3.4-c): 失败约束聚集只是【触发
        诊断的信号】,不是加密依据。流程: 收到带失败范围+诊断原因
        的细化请求 → 用新鲜占据证据在请求范围内做局部连通细查 →
        确认粗表示遗漏可用连通且有分辨率不足依据 → 在预算内
        (节点数/范围/计算时间)细化。细化后未增加有意义路线选择
        → 记录"本轮细化无改善",同一几何上下文不重复无效加密。
        细化改变的是表示分辨率,不是连通语义(两层身份,见上)。
        验收不是"节点变多了",而是: 原遗漏的接近方案被表达、重复
        失败减少、有效运动增加、身份维护成本受控。

  存什么: 已知自由空间的连通结构 + 风险语义([F1]) + 命名。
  risk 属性注记(v3.4-e): 边属性 risk 只承载【几何风险】(来自地图
        与地形模型,[F1] 供料);运动适用性依赖方向/速度/合同,归
        约束层(§5)带工况表达——不得压成全局无条件的单一风险值,
        否则几何与执行两种知识在边上混账(违反单一来源,§7)。
  刻意不存: 格子级证据(度量层的)、任务意志(Explorer 的)、未知区域
          (网只描述已知;未知由边界环+度量层 unknown 掩膜描述)、
          区域可达性结论(那是 Explorer 经证据分类的裁决)。

  写者: global_representation 单权威——吃 Local GridMap 切片(P3,
        v3.1-b 确认:原料不是 Explorer 栅格),增量生长,BranchRegistry
        裁定四类谱系事件。
  读者: Explorer 副本——估价(多源 Dijkstra)、挂接(frontier→branch)、
          路线(分支序列)、承诺视图(区域工作集)、失败证据挂载。

  派生视图(不驻留,按需生成):
            脊线(spine,参考提示/可视化)、区域舱室(掐点围合,承诺对象)、
            路线(分支序列,拓扑权威的路线形态)。

  凭什么独立: 它是唯一的身份权威和路线基底。删了它:区域没有稳定名字
          (回到 IoU 认人)、远距估价退化成全图 A*、失败证据无处持久、
          返航没有分支序列可反向遍历。

  接口: ① 吃 Local GridMap 切片(P3);② 被 Explorer 副本消费(P4);
          ③ 向 Registry 供特征(Q3);④ 承诺/失败/任务的属性宿主(Q4)。

  演进落点: G1(全量重算→波前增量,C++ 化)、E1(BranchRegistry,
          【独立于网格引擎先行】)、F1(边风险语义)、TRG/RB-TRG 吸收
          (风险边+机体感知)。
  失败模式: 早期特征抖动(确认迟滞管)、merge 判据([草案])、
          C++ 维护成本(T5 最大单项)。
  前提: 掐点处网格/度量层密度足够(Q1 兜底);区域身份锚在掐点等
        稳定几何特征上,不锚在采样点上。

2.3 执行视图(Local/scan_planner_node 持有;Q5 的权威)

  数据结构: 0.05m 三维滑窗 10×10×5m(~80MB 固定)log-odds + 膨胀层
          + TLS 快照。滑动跟随机器人,窗外清零。
  权威表述(v3.1-d): 本层是【执行视图】——有噪声、有延迟、有未知
          区域的局部估计,不是"瞬时几何真相"。
  存什么: 机器人周围 10m 的局部估计(体素级),供终验/扫掠/优化器
          逐体素查询。
  刻意不存: 滑窗外的一切(即用即丢是特性)、历史、身份、区域、
          可通行性结论(那是地形模型的输出)。

  写者: SCAN 融合回调(20Hz)。
  读者: FSM 0.02s 逐样终验、制动扫掠、优化器查询、安全回调。

  凭什么独立: 它是唯一有**体素分辨率 + 实时性**的一层——终验要问
  "这个 0.05m 体素下足印撞不撞",度量层(0.2m)和渔网(拓扑)答不了。
  与度量层的关系: 分辨率差 4×、维度不同、语义不同(log-odds vs 证据)
  ——故意不同步(1.3)。局部用最新最细的估计执行,全局用保守积累的
  判断决策。

  分歧处理(v3.1-e): 局部可拒绝执行,但拒绝必须分类(§1.6 补充):
    实际占据反证 / 地图过期 / 姿态变化 / 预算耗尽 / 运动合同不适用。
    分类决定: 就地重查、触发局部重查、还是上报 Explorer。
    一次局部拒绝【不】自动改变持久拓扑,【不】自动把区域判成不可观测。

  演进落点: F1(足迹单 z 圆盘→机体带检查)、A5(deBoor 分配)、
          A6(refine 验证缺口)、[可选] 前瞻小图(轨迹级风险候选)。
  失败模式: 窗口内噪声 → 终验抖动 → blocked 频发(协议当日常的
          上游原因之一——居中代价修复的动机)。

3.1 Explorer(度量与决策)

  一句话: 系统的"记忆与意志"层——拥有度量层与结构副本,独占观测任务
  生命周期与进度解释权,把意志与经验附着到结构 ID 上。

  拥有: 度量层(证据栅格+chunk)、结构副本+承诺视图、进度解释器
        (事实流消费)、观测任务生命周期、任务/失败/冷却记忆、
        决策拍流水线。
  不拥有: 身份颁发(Global Registry)、渔网权威(Global)、
        执行方式与安全反射(Local)、运动尝试终局(Local)。

  内部四块(v3.1:按职责拆分,frontier_explorer.py 退为订阅/调度/发布):
    a) 观测证据   : 度量层维护(融合/证据/摘要)
    b) 任务生命周期: observation_lifecycle 为任务对象基础;完成判定
       只读真实观测证据
    c) 任务选择   : 读剩余需求与路线可用性
    d) 承诺管理   : 只处理明确的进入/保持/释放/中断

  主链(一次运行):
    Explorer 从真实观测证据中确定剩余信息需求
    → 选择区域、拓扑路线与允许的观测范围
    → Local 在该范围内选择站位和运动候选
    → 候选通过几何、动力学、制动和交接验证
    → Controller 确认并执行具体轨迹
    → 执行侧报告轨迹结果;传感器持续提供观测证据
    → Explorer 根据观测证据决定任务是否完成
    → 完成则提交下一任务;未完成则决定下一次观测尝试

  这里没有第二本观测账本。但仍有任务、运动请求、执行轨迹三种生命
  周期——它们是三个不同对象;重构目标不是合成一个状态机,而是使
  它们之间的关系明确。

  接口: P1 下发任务/路线;P2 消费事实流;P4 消费结构 delta;
        失败证据经 global_representation 固化。

  已实现: 证据制栅格、两级承诺机制、task_mode 域内站位、
  120+ 状态机测试。
  [草案] 进度解释器与事实流的正式协议(T1.5)、承诺子树视图。
  [待填] region churn 基线数字;走廊域参数 R;兄弟摘要刷新策略;
         局部风险网格的查询接口规格。

3.2 Global(结构与身份)

  一句话: 系统的"命名与连接"层——渔网权威 + 身份注册,独占结构身份;
  不做规划,不做意志,不裁决区域可达性。

  拥有: 渔网权威(增量波前网格)、BranchRegistry(四事件)、锚点、
        delta/snapshot 分发、失败证据的图级固化(带来源/适用运动条件/
        撤销条件)。
  不拥有: 任务意志(Explorer)、度量证据(Explorer)、执行方式与
        安全反射(Local)、区域可达性终局(Explorer 经证据分类)。

  内部四块:
    a) 结构构建: patch → 增量波前网格(算法可更换,身份不随之重写)
    b) 身份注册: BranchRegistry(四事件;独立于网格引擎先行)
    c) 路线查询: 分支序列上的路线/估价
    d) 约束存储: 失败证据固化(来源/适用运动条件/撤销条件)

  约束存储的边界(v3.1): 把某次起步失败存到图上,≠ Global 有权把
  整条分支宣布为不可通行——约束必须带来源、适用条件与撤销条件。

  接口: P3 吃 Local GridMap 切片;P4 分发结构给 Explorer 副本;
        Registry 供特征(Q3);约束存储宿主(Q4)。

  已实现: 累积拓扑图、稳定 ID(uint64 量化)、delta/snapshot、
  显式封锁确认(3-patch 模式)、失败证据固化(SCOPE_VIEWPOINT)。
  [草案] BranchRegistry 算法(四事件状态机——【独立于网格引擎先行】)。
  [待填] merge 事件规则细节;网格分层管理(大尺度稀疏化);
         网格节点密度策略(掐点处加密);多机器人身份上收(方案 B)。

3.3 Local(执行与反射)

  一句话: 系统的"行动与反射"层——拥有执行窗口、优化器、安全反射,
  独占执行方式与安全停车;发布纯事实流。

  拥有: 执行视图(0.05m 滑窗)、B 样条优化器、A* 重连、安全反射
        (制动扫掠/硬停)、事实流发布、STOPPING 状态、运动尝试终局。
  不拥有: 观测任务终局(Explorer)、结构身份(Global)、长程记忆。

  内部四块:
    a) 目标与候选生成: 回答"可以尝试什么"
    b) 统一验证       : 回答"这个候选是否满足同一合同"
    c) 执行协调       : 回答"Controller 实际装载了哪个版本"
    d) 安全仲裁       : 决定继续 / 后台替换 / HOLD

  现有 FSM 逐步退为编排器,不再增加互相组合的恢复标志。

  接口: P2 发布事实流;P1 消费任务/路线;安全反射独占(不经全局)。

  已实现: 事务化交接、clearance-limited、受限步态、死区校准常数、
  事实流前身。
  [草案] STOPPING 状态 + 停止三修复(见 §6,修法已收窄)。
  [待填] stop-probe 标定(真实制动延迟/减速度/瞬态幅度);
         前瞻小图规格(若需轨迹级风险候选)。

4.0 总原则(v3.3 修订)
  载体原则(v3.1 保留): 不新增状态话题。现有 ExecutionState 已带
  request_id/task_id/task_version/trajectory_id 并以 ~0.1s 节流发布
  (closed_loop_controller:165-184)——事实流的载体就是它的扩展。
  汇总原则(v3.3-a): "不新增话题"不是正确性标准,唯一来源才是。
    - 执行协调组件是对外执行状态的【唯一汇总出口】(现有落点
      [待填]: Local FSM 侧协调层);
    - Controller 与 Local 各自拥有自己产生的结果,汇总组件只归并
      转发,【不重新裁决】——无权把"尝试穷尽"改写成"任务失败",
      也无权把"轨迹走完"改写成"任务完成";
    - 每个字段/每个对象结果有且只有一个来源(表见 §7);两份状态
      交替到达由汇总出口归并,不允许 Explorer 自行解释两份并行
      状态流。
  正交维度原则(v3.3-a): 当前运动状态(STOPPING/STOPPED)与对象终局
  (SUCCEEDED/EXHAUSTED/SATISFIED)是两个正交维度,【不】塞进单一
  互斥枚举——"已停稳+轨迹结束+任务未满足"必须可直接表达。

P1 任务下发(Explorer → Local)
   载体: /observation_task(task_mode)或 /initial_path(兼容模式)
   内容: task_id/version · region/branch 引用 · coarse_route ·
         corridor_radius · 剩余 target_cells(过滤后) · 建议站位
   纪律(v3.3-c 收窄): "单号挂起"只约束【请求-响应对】——同一任务

5. 承诺 = 区域工作集选择(子树是派生视图)
--------------------------------------------------------------------------------

语义(v3.3-e 修订): 承诺选择一个**区域工作集**。三个"图"概念分离,
不共用一个字: 底层是【允许有环的空间连接图】;身份谱系关系形成
【DAG】;承诺展开生成【树形视图】——"子树"只是派生视图,不改变
底层连接关系,也不改变谱系。

  形成: G1 形成 → 展开该区域工作集,残值门复位
  保持: 残值门(exhausted/stagnant)+ 方向门(机制不变,键换 branch)
  释放: 残值耗尽 / 持续不可达 / 观测完成
  中断: 强制返航 / 用户取消 / 健康故障 / 明确通道阻断
        —— 与正常完成同为【合法转换】,走同一转换入口
  转移: 完成驱动的 handoff(正常);中断驱动的退出(异常,同等合法)

五类合法转换(v3.1:全部经同一承诺转换入口):
  1 观测完成(observation SATISFIED)      → 提交下一任务
  2 强制返航(任务需要/用户指令)          → 反向遍历已走分支序列
                                            (仅作候选路线;须过当前
                                            通道约束与反向可执行性
                                            检查——走过 ≠ 当前可安全
                                            返回,v3.3-e)
  3 用户取消                              → 释放承诺,保留区域记忆
  4 健康故障(supervisor 门控)            → 中断,状态保留
  5 明确通道阻断(路线级证据)             → 释放承诺,区域标受阻
  每类转换的验收: 该转换有测试覆盖;转换后无悬空的承诺状态。

收益表述(v3.1-h 降级):
  "漏释放不可能再发生"不是设计承诺,是验收条件——前提是所有终止原因
  都经过同一承诺转换入口,并且有测试覆盖。覆盖完成之前,只声明
  "转换入口统一了"。

失败证据的作用域(v3.2-c):
  挂到图上的约束必须带三要素: 来源(哪个任务/哪次尝试产生)、适用
  运动条件(哪个站位、哪个合同、哪次起步)、撤销条件(什么观测出现
  时失效)。作用域由证据类型决定,不由存储位置决定:
    一次起步失败   → 约束该站位/该合同的再次起步
    路线级阻断     → 约束分支(转换 5,须路线级证据)
  把某个起步失败存到图上,不等于 Global 有权把整条分支宣布为不可
  通行;越界使用约束 = 回到"宽泛名字被另一层解释成更大失败"的老路
  (§1.1 禁令)。

失败记忆机制(v3.4 新增;三通道流转):
  证据锚世界坐标(v3.4-b): 失败段几何+接近方向+适用运动条件+撤销
      条件是证据本体;边 ID 是索引,不是存在依据。结构重建/细化时
      按空间范围重新挂接——只挂到失败段实际覆盖的边,不复制全量
      约束,不扩大作用域,不因旧边删除而丢失。
  与结构层分离: 约束 overlay 挂在边引用上,不改变连接结构、身份
      与谱系;snapshot/delta 替换的是结构副本,【不动】约束层。
      Explorer 本地待确认 + Global 已确认,按 evidence_id 去重
      转正(与 B6"副作用恰好一次"同构)。
  两级时序: 【立即应用约束】(Explorer 收到证据当轮生效,不等
      Global)与【异步修复表示】(约束聚集触发诊断 → §2.2 细化
      流程)。不预设具体延迟,由预算与实测确定;后者是可选的异步
      分支,不是每次失败必经的一层。
  恢复动作分流(v3.4-f): "渔网表达不出连接"(结构表示不足)与
      "Local 生成不出轨迹"(采样/候选形态/允许域/优化代价/运动
      认证问题)是两个问题——前者走表示修复(§2.2),后者在 Local
      对应组件处理;Local 候选生成不以渔网枚举绕行为前提(D-5),
      左/中/右绕行不需要变成三条 NetEdge。

兄弟摘要: 未承诺区域保留残值摘要(剩余未知格),供释放后重选;
  摘要每 map_revision 刷新(按挂接归组,一次 dict 归并)。

未挂接桶(开阔地带回退): 几何身份(chunk 块级)承接,视图留槽位。

6. 停止语义(v3.1:STOPPING 三分 + 三缺陷分别核验)
--------------------------------------------------------------------------------

STOPPING 三分(v3.1-g): 停车期间,
  继续计算下一任务          ✓(不受影响)
  准备下一运动候选          ✓(不受影响)
  授权候选开始执行          ✗(由执行侧按实测状态与安全认证决定)
不把正常减速当成执行停滞,不启动不兼容的运动;观测完成、下一任务准备、
取消、超时和健康检查仍然运行。

STOPPED 确认: 由实测速度、角速度以及必要的姿态条件确认;ETA 是预测,
不得作为停稳判据。

三个停止缺陷的核验状态与修法:
  缺陷1 停止命令斜率穿越死区 —— 成立(advance_limited_command 为通用
       限幅,0.30→0 需 0.6s,30 拍未定义命令)。修法【收窄】: 归零豁免
       只适用于【显式停止意图或已定义的步态切换】;普通减速请求不得被
       转换为反复启动与停止。命令归零与机器人实际停稳是两个阶段,
       修复后分开验证。
  缺陷2 急停样条 × 步态校准 —— 【已有防护,v3.2-a 核验】: 静止样条
       已转版本化 soft_hold("STATIONARY_HOLD_TRAJECTORY",
       closed_loop_controller.cpp:321,直接返回,不再进入步态校准与
       P 位置回拉路径);soft-HOLD 分支(:664-671)已发布零平移零偏航。
       重构约束: 此防护必须保留,e-stop 不得退回"发静止样条"路径;
       原"恒 0.30 前向"缺陷描述保留为历史记录。
  缺陷3 停止携带偏航 —— 【收窄】: soft-HOLD 分支(closed_loop_controller
       :664-671)已直接发布零平移零偏航;publishStop(yaw_command) 仅
       用于显式 heading alignment。重新表述: "停止路径与 heading
       alignment 的耦合在观察上可能呈现为旋转——用 stop-probe 实测后
       定性,区分带意图的对准停止与意外旋转"。

标定([待填]): stop-probe 实验(行走中突然归零,记录减速曲线/停止
  距离/瞬态幅度)→ 实测参数喂回 brakingSweepHorizon(现值 0.32 m/s²
  与 0.30s 延迟为拍的)→ 安全余量从"拍的模型"变为"实测模型"。

10. 决策记录(为什么不做 XX)

  D-1 不做语义层: Hydra 的 Rooms/Objects 需要检测/分割,是另一问题域;

  D-5 全局居中代价取消(Option B): 几何权威归局部,居中偏好长在局部
      优化器。【v3.2-a 状态校准】局部优化器已存在独立 preferred-
      clearance 代价(bspline_optimizer.cpp:1228 addPreferredClearanceCost,
      注释"平滑偏好非硬证书")——剩余工作不是新建代价,而是:
      (a) preferred margin/权重标定(现推离分界 preferred 0.20m 待实测);
      (b) 验证其与"几何权威归局部"的一致性。

      所有 clearance/风险信息: Explorer 保留粗略风险估价用于接近

  D-9 外部基线黑盒化: LRAE/DARE/ARiADNE/TARE/TRG 只跑对照,不拆内部;

      现有 0.1s 状态流已带四个 ID,缺的是字段与语义收敛(v3.1-a)。
  D-11 异常退出合法化: 强制返航/取消/健康故障/通道阻断与正常完成同为
      合法转换;不为了简化承诺而关闭异常出口(v3.1-f)。
  D-12 Registry 先于网格引擎: 身份迁移 bug 与图提取 bug 必须可区分
      (v3.1-f);两者耦合实施会让失败归因不可能。
  D-13 观测来源标记位宽收窄 u64→u32: sensor_observed 存的是"最后
      一次被观测打中的 revision"而非 1 bit 布尔——完成判定要区分
      "任务创建前打到"与"任务期间打到"(与 initial_sensor_revision
      比较),版本号语义必需。但位宽非必需: 度量层融合 0.25s 节流
      (约 4Hz)下,u16 约 4.5h 即溢出,u32 上限约 34 年连续运行,
      收窄零语义损失。收益: 每格 8B→4B,每格合计 11B→7B,
      100×100m 探索面积 11MB→7MB。逐格记录本身保留(Mid360
      非重复扫描点云稀疏,遮挡后方/视野边缘格子不能凭"机器人
      路过"推断——robot-centred seeding 已被代码注释排除)。
      (2026-10-07 存储审计决策;现实现 grid.py:212 仍 u64,待改,
      改动后须过完成判定单测。)
  D-14 执行失败结论不得代替几何证据: 重规划不得直接改写 Global 的
      空间连接结论;执行失败只产生有作用域的证据(§5 失败记忆机制)。
      一次验证失败可能同时携带可核验的占据反证(如碰撞点的传感器
      确认)——经核验后可进入结构层既有流程(反证→局部删除);禁止的
      是把失败结论直接当几何事实写结构。网格细化是【诊断后的表示
      修复】,不是重复失败的通用恢复解。最终验证的不是"节点多了",
      而是"遗漏的接近方案被表达、重复失败减少、有效运动增加、
      身份维护成本受控"。(2026-10-07,第三轮设计评审)

12.1 行为验收(评审"最重要的验收"清单,重构每阶段跑一遍)

  B1 后继提交延迟      拆两段分别实测(v3.3-c): B1a 信息满足→后继
                       发布;B1b 后继发布→Controller 实际切换。
                       合并统计会掩盖"全局刷新快、局部一直等"。
                       (现状: handoff 后等待 successor ACK 才放行
                       安全执行,649d868。)超阈值 = 回归。
  B2 安全旧前缀存续    旧前缀能持续执行到【合法切换点】,【前提是
                       期间仍然安全】——新观测发现障碍必须允许提前
                       打断(v3.3-c)。停顿判定收窄: 【无必要的协议
                       停顿】是回归;【真实安全原因的停车】不是回归;
                       两者靠原因字段+时间记录区分,不靠位移猜。
  B3 失败不传染        候选失败后,后续规划改变的是【路径/起步假设】,
                       不是区域的可达性结论;一条路径的失败不误杀
                       整个 Frontier 的信息需求(对应 §5 作用域纪律)。
  B4 等待有出口        静态地图下"就地等待重查"类分支(§1.6 地图过期)
                       必须有明确退出条件(重试上限/revision 前进/
                       上层超时),不允许无限等待。
  B5 取消不复活        任务取消后,旧执行不得被【重新接受候选或
                       再次授权执行】——靠 task_version/
                       trajectory_id 版本栅栏+独立授权撤销(v3.3-c)。
                       验收同时观察: 执行授权/命令输出/实际停车;
                       命令归零后的制动位移是动力学,不算栅栏漏。
  B6 副作用恰好一次    同一对象的同一终局可以重复传输,但对决策的
                       【副作用】恰好一次(v3.3-b)——靠"消费确认+
                       对象 ID+终局 ID"去重,不靠"收到过就忽略";
                       消费过程失败与重启恢复要有测试。

12.2 三条端到端演练(把上述验收钉到具体场景;每条都可证伪)

  演练A 正常完成 → 滚动交接(逐步展开见 PROCESS_WALKTHROUGH §3)
    链: 观测证据解析 → Explorer 宣布 SATISFIED → 承诺转换入口1 →
        后继任务准备与下发(P1: 准备不授权) → 候选装载(ACK=
        装载结果) → 旧前缀执行至合法切换(期间仍须安全) →
        版本化交接 → 旧对象退役入终局缓冲。
    通过: B1a/B1b 分别实测;B2 存续且停顿可归因;状态流里
        REACHED/STALLED 与新解释器无双头解释。
    失败信号: 无必要的协议停顿/回退/重复起步(安全原因的停车
        除外,按原因字段+时间记录区分)。

  演练B 起步失败 → 区域保留(逐步展开见 PROCESS_WALKTHROUGH §4)
    链(v3.3-d 补层): 候选起步被拒(装载拒绝或统一验证拒绝) →
        分类(§1.6)并记录失败类型/位置 → 【同一任务内】改变起步
        或路径假设,有界重试(每次记录"相较上次改变了什么";新
        请求 ID 不算改变) → 候选族穷尽或预算尽 → Local 宣布
        EXHAUSTED → failure_evidence(三要素)入图,作用域=
        站位/合同 → Explorer 保留信息需求,调整接近方案或站位
        (避开与失败出发连接重叠的站位)。
    通过: B3 后续决策仍把该区域列为候选;失败证据在【满足其自身
        撤销条件】时被撤销(不是"有新帧就撤";别处地图更新不清
        当前出发方向的失败记录)。
    失败信号: 一次起步失败后该 Frontier 永久消失;或换站位后
        重复同一段失败出发连接。

  演练C 取消 → 迟到消息(逐步展开见 PROCESS_WALKTHROUGH §5)
    链: 用户取消 → 承诺转换入口3(释放承诺,区域记忆保留) →
        版本失效+RETIRE_TASK 栅栏+执行授权撤销(三道闸) →
        命令归零 → 实测停稳确认 → 迟到 ACK 到达。
    通过(v3.3-c 收窄): 迟到消息被版本栅栏拒绝且拒绝无副作用;
        观察三要素——执行授权(不得重新接受旧候选/再次授权)、
        命令输出(无持续非零命令)、实际停车(实测停稳,制动位移
        属动力学)。承诺状态无悬空。
    失败信号: 取消后旧执行被重新授权或旧候选被重新接受;持续
        非零命令输出。(单纯制动位移不是失败信号。)
